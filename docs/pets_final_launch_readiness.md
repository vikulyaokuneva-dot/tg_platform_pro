# PETS — готовность к финальному запуску

Дата проверки: 2026-10-27. Этот документ описывает подготовку, а не разрешение
на публикацию: `PETS_PUBLISH=0`, Telegram не вызывался, cron не включался и
ветка не объединялась с `main`.

## Первый пост

Финальный preview находится в
`runs/pets_final_launch_readiness/first_post_preview/`.

* Использован сохранённый результат единственного прежнего вызова GigaChat:
  новый платный вызов не выполнялся.
* OGL v3.0 теперь трактуется как часть атрибуции, а не как неподтверждённое
  числовое утверждение. Любые другие числа по-прежнему блокируют материал, если
  их нет в factual brief.
* Фотография: собака в домашнем помещении, автор `Shixart1985`, лицензия
  `CC BY 2.0`, страница файла Commons и условия лицензии сохранены в preview.
* Для проверки дубля SQLite был временно скачан из `pets-state` в read-only
  режиме. Проверка не нашла совпадения; production SQLite не изменялась.
* Финальный статус preview: `ready_for_manual_approval`. Это не означает, что
  материал уже добавлен в очередь или отправлен в Telegram.

## Безопасный автономный маршрут

```
Идеи из Telegram / тематических сайтов
        -> тема-кандидат (не факт и не текст для перепечатки)
        -> независимый factual brief из разрешённого источника
        -> лицензии + редакционный фильтр + дедупликация
        -> GigaChat только по явному лимиту и разрешению владельца
        -> тематическое Commons-изображение с правами
        -> durable SQLite-очередь
        -> максимум один Telegram-пост за запуск и за сутки
```

Telegram-материалы PETS 4.4/4.5 остаются только источником идей. Они не
передаются в GigaChat как текст статьи и не могут сами по себе попасть в
очередь. Без factual brief, подтверждённых прав и подходящей фотографии
материал переводится в `review`.

Автопополнение реализовано в `jobs/pets/job.py`: при одновременном явном
включении внешних factual-источников, реального GigaChat и production queue
вызывается `replenish_verified_queue`. При отсутствии кандидатов или при
неудаче Commons очередь не дополняется, а материал остаётся `review`; старый
или случайный материал не публикуется как fallback.

## GitHub Actions

`pets_channel.yml` оставляет cron-выражение 12:00 МСК документированным, но
плановый job не запускается, пока repository variable
`PETS_AUTONOMOUS_SCHEDULE_ENABLED` не равна `1`. Сейчас её следует оставить
равной `0` или не создавать вовсе.

Дополнительные защиты:

* `PETS_PUBLISH_LIMIT` в workflow зафиксирован как `1`; конфигурация также
  ограничивает локальный запуск максимум одним сообщением.
* Реальный GigaChat возможен только в ручном `workflow_dispatch`, когда
  включены `use_live_gigachat`, `PETS_ALLOW_LIVE_AI` и `PETS_AI_ENABLED`.
  В schedule этот режим не включается.
* SQLite восстанавливается из отдельной ветки `pets-state`; SHA/CAS и
  workflow concurrency защищают от конкурирующих записей.
* Ошибка генерации, прав, фотографии, durable-state или доставки переводит
  материал в `review`; автоматической повторной отправки после неопределённой
  доставки нет.

## Настройки перед контролируемой публикацией

**Secrets:** `AI_AUTOMATION_BOT_TOKEN`, `PETS_CHAT_ID`, `GIGACHAT_API_KEY`
(последний нужен только для отдельной генерации, не для отправки готового
поста).

**Variables:**

* `PETS_PUBLISH=0` до отдельного разрешения;
* `PETS_STATE_BACKEND=github`;
* `PETS_STATE_REPOSITORY=vikulyaokuneva-dot/tg_platform_pro`;
* `PETS_STATE_BRANCH=pets-state`;
* `PETS_STATE_PATH=pets/pets_channel.db`;
* `PETS_AUTONOMOUS_SCHEDULE_ENABLED=0` или отсутствует;
* `PETS_AUTONOMOUS_REPLENISH_ENABLED=0` или отсутствует;
* `PETS_AUTONOMOUS_GIGACHAT_LIMIT` не задавать до отдельного решения о
  платной генерации. После разрешения допустимо только значение `1`: SQLite
  резервирует один вызов на московский календарный день до обращения к
  провайдеру, поэтому неоднозначный сбой не вызывает платного повтора.

Перед единственным реальным тестом нужно: вручную подтвердить финальный preview
и его перенос в production queue, проверить, что бот добавлен администратором
в нужный канал, выполнить preflight, затем отдельный controlled publish. До
подтверждения владельца не менять `PETS_PUBLISH` и не включать расписание.

После успешного контролируемого поста требуется проверить `message_id` и
durable-state, а уже затем отдельным решением установить
`PETS_AUTONOMOUS_SCHEDULE_ENABLED=1` для ежедневного запуска в 12:00 МСК.
Автопополнение при этом остаётся выключенным: его можно включить только
отдельно через `PETS_AUTONOMOUS_REPLENISH_ENABLED=1` и конечный лимит
`PETS_AUTONOMOUS_GIGACHAT_LIMIT=1`.
