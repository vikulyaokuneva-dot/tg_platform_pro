# PETS 3.1.1 — проверяемые источники кандидатов

## Назначение

`python -m jobs.pets.source_candidates` — отдельный ручной dry-run для
сбора доказательств. Он не вызывает GigaChat, не отправляет Telegram-сообщения
и не использует рабочую SQLite канала PETS. По умолчанию кандидатная SQLite
располагается отдельно: `data/pets_source_candidates.db`; для испытаний следует
задавать `PETS_CANDIDATES_DB_PATH` во временной папке.

Результат: `runs/pets_source_candidates.json` и
`runs/pets_source_candidates_diagnostics.json`. В GitHub Actions те же файлы
прикладываются как артефакт на 14 дней только при ручном input
`collect_source_candidates=true`.

## Включённые коннекторы

| Источник | Метод | Что сохраняется | Статус в конвейере |
| --- | --- | --- | --- |
| Frontiers in Veterinary Science | официальный NCBI PMC E-utilities: `esearch` + один ограниченный `efetch` XML | DOI, заголовок, авторы, год, ссылка PMC, лицензия статьи и дословные факты из аннотации | кандидат или `review` |
| PubMed Central Open Access | официальный NCBI PMC E-utilities, только full-text XML | те же поля | кандидат или `review` |
| FDA animal-food enforcement | официальный `api.fda.gov/food/enforcement.json` | номер recall, продукт, причина recall, дата, ссылка на запись | только `review` |

Запрос Frontiers принимает только статьи, в заголовке которых прямо указан
`dog/canine` или `cat/feline`, и тема которых прямо относится к поведению,
благополучию, обогащению среды или обучению. Это исключает случайные материалы
о других животных.

FDA-записи — государственные safety-сигналы, а не рекомендации владельцу.
Они никогда не становятся `candidate_ready` автоматически.

## Лицензии и прослеживаемость

Для каждого факта сохраняются точная лицензия, ссылка на её подтверждение,
автор, URL материала, обязательства по атрибуции, разрешённость адаптации и
время проверки. `CC BY-SA` остаётся `CC_BY_SA`; она не переименовывается в
`CC_BY` и требует сохранения той же лицензии для адаптации. Неизвестные и
несовместимые лицензии блокируют автоматическую переработку.

Аннотация используется только как источник явно записанных в ней фактов:
название или метаданные сами по себе не создают утверждения. Каждый кандидат
содержит связь `утверждение → статья/URL`.

Клинические случаи, диагностика, лечение, лекарственные темы, онкология,
инфекции и другие медицинские сюжеты удерживаются в `review`, даже если
лицензия допускает адаптацию. Один эксперимент не превращается в универсальный
совет для владельцев.

## Намеренно не включено в автоматический поток

- CDC Healthy Pets остаётся выключенным до отдельного подтверждения допустимого
  способа доступа и условий повторного использования.
- openFDA adverse-event records не используются для генерации советов: это
  необработанные сообщения о нежелательных событиях. Они допустимы лишь как
  сигнал для ручной проверки.
- `Animals` и `Veterinary Sciences` (MDPI) исследованы как потенциальные
  источники open-access статей, но не подключены: в текущем этапе уже есть два
  работающих полнотекстовых источника PMC; для MDPI нужен отдельный
  документированный контракт получения полного текста и лицензии на уровне
  каждой статьи. Метаданные/аннотации без такого подтверждения не достаточны.

## Безопасный ручной запуск

```powershell
$env:PETS_PUBLISH = '0'
$env:PETS_CANDIDATES_DB_PATH = Join-Path $env:TEMP 'pets311-candidates\candidates.db'
python -m jobs.pets.source_candidates
```

В GitHub Actions запускать только вручную: `PETS channel (manual dry-run)` →
`collect_source_candidates=true`; все остальные opt-in для AI и публикации
оставить выключенными. Cron в workflow отсутствует.
