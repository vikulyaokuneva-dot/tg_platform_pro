- Реальный source-only dry-run выполнился в отдельной SQLite внутри `runs/`:
  27 уникальных материалов, 1 `editorially_ready`, 2 `review`. Все адаптеры

  ошибочный ответ остаётся в `review`.

## Wikimedia Commons

Проблема прежнего прогона была диагностической: скачивание могло завершиться
403 для thumbnail либо превышением лимита размера для оригинала, но старый код
сохранял только сокращённую строку исключения.

Теперь для thumbnail и original записываются очищенный URL без query-параметров,
HTTP-статус, разрешённые заголовки, MIME-тип и фактический размер байтов. На
повторной контрольной проверке выбранное фото Commons прошло:

- `HTTP 200`, `image/jpeg`, `1,054,752` байта;
- версия: `thumbnail`;
- результат: `attached`, локальный файл `photo.jpg`.

При невозможности скачать любую версию результат строго
`image_download_failed`; существующая ссылка не считается локальным файлом и
не разрешает статус `ready_for_manual_approval`.

## Рекомендация

Технически система готова к **одному отдельному контролируемому** вызову
GigaChat: она передаёт только проверенный factual brief, ограничивает вызовы,
фиксирует ответ и удерживает результат на ручной проверке. Перед таким вызовом
нужно отдельно подтвердить число вызовов и лимит расходов. Telegram-публикация,
cron и `PETS_PUBLISH` должны оставаться выключенными.

## Ограничения

- HTTP-доступность Commons может меняться между запусками. Ошибка загрузки не
  подменяется другим изображением.
- Автоматические проверки не заменяют ручную редактуру и не переводят
  публикацию в `post_ready`.
- Production `pets-state` в испытаниях не открывалась на запись.
