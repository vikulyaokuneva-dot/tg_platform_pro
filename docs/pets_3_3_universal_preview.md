# PETS 3.3 — универсальная подготовка постов из factual briefs

## Назначение

`python -m jobs.pets.universal_preview` готовит до трёх изолированных
предпросмотров только из `editorially_ready` кандидатов JSON-артефакта. Он не
создаёт материалы, не изменяет SQLite `pets-state`, не вызывает Telegram и не
включает публикацию.

Источник по умолчанию: `runs/pets_source_candidates.json`. Его создаёт уже
существующий source-only dry-run. Для локальной проверки можно явно указать:

```powershell
$env:PETS_PUBLISH = '0'
$env:PETS_FACTUAL_BRIEFS_PATH = 'runs\pets_3_1_3_artifact\pets_source_candidates.json'
$env:PETS_33_USE_LIVE_GIGACHAT = '0'
python -m jobs.pets.universal_preview
```

## Условия допуска factual brief

Модуль отвергает материал, если нет корректного DOI или HTTPS-источника,
`editorial_status` отличается от `editorially_ready`, права на адаптацию не
подтверждены, меньше трёх traceable facts или отсутствуют ограничения
исследования. Он не дополняет подборку демонстрационными материалами.

## Режимы текста

- По умолчанию создаётся `offline_factual_outline`: источник, факты и
  ограничения видны редактору, но это **не готовый пост** и имеет статус
  `review`. Так система не выдаёт машинный перевод фактов за оригинальный
  русскоязычный материал.
- GigaChat возможен только при двух флагах: `PETS_33_USE_LIVE_GIGACHAT=1` и
  `PETS_33_OWNER_APPROVED=1`. Число вызовов дополнительно ограничивается
  `PETS_33_MAX_GIGACHAT_CALLS` (0–3). В workflow PETS все три значения
  принудительно равны нулю — запуск Actions не способен израсходовать AI.

Даже успешный текст проходит проверку чисел, источников и опасных формулировок;
семантическая редакционная проверка остаётся обязательной.

## История и дубликаты

`PETS_HISTORY_DB_PATH` открывается SQLite URI в режиме `mode=ro`: таблицы не
создаются, миграции не выполняются, запись невозможна. Уже опубликованные DOI,
source URL и очень похожий текст блокируют preview. Если локальная история ещё
не восстановлена из `pets-state`, результат остаётся `review`, а диагностика
фиксирует `history_missing` вместо предположения об отсутствии дубля.

## Изображение и артефакты

Для каждого выбранного brief строится свой строгий visual contract (вид
животного + контекст темы). Wikimedia Commons-поиск принимает только фото с
автором, страницей файла, лицензией и подтверждённым смысловым соответствием.
Для preview запрашивается ограниченная thumbnail-версия; данные о правах всегда
связаны с исходной страницей файла.

PETS 3.3.1 различает два независимых состояния: проверенная ссылка и локально
прикреплённый файл. Загрузка сначала пробует thumbnail, затем исходный файл.
Для каждой попытки в JSON сохраняются очищенный URL без query-параметров,
HTTP-статус, безопасные response headers (`Content-Type`, `Content-Length`,
`ETag`, `Last-Modified`, `Cache-Control`), MIME и реальный размер байтов.
Ответы не-`image/*`, меньше 15 KiB или больше 10 MiB отклоняются. Если ни одна
версия не подходит, фиксируется `image_download_failed`; ссылка не подменяется
случайной фотографией и preview остаётся `review`.

В `runs/pets_universal_preview/` сохраняются:

- `pets_universal_preview.json` и `pets_universal_preview_diagnostics.json`;
- отдельная папка каждого preview с Markdown, JSON, validation и скачанным
  фото (если оно прошло контракт и загрузку);
- причины каждого `review` и отклонённого brief.

GitHub Actions получает новый ручной флаг `create_universal_preview`. Он сперва
собирает factual briefs и затем запускает только этот offline-конвейер. Cron и
Telegram-публикация не меняются и не включаются.
