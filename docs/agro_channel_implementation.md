# Agro channel (jobs/agro) — реализация вертикального среза

Дата: 15.09.2026. Рабочая ветка `tg_platform_pro`, коммитов от этой задачи нет
(коммит — за пользователем). Документ заменяет пропавший «architecture audit»
предыдущего шага (файл `docs/agro_channel_architecture_audit.md` так и не был
записан — его выводы перепроверены кодом и встроены сюда).

## Итог

Второй Telegram-канал («Агро Практика») работает как **platform-native job**
`jobs/agro` поверх существующего ядра: discovery → fetch → extraction →
правилый агро-классификатор → extractive-пост → редакционные гейты →
telegram-публикация. Production-канал (AI-автоматизация), E/F-механизмы,
headline-система (Task J) и frozen-классификатор — **не изменены**
(`git diff` по ним пуст; итоговый тест после addendum — см. ниже, 132 passed:
111 baseline + 21 агро).

## Архитектурная граница (зафиксировано, а не обошло молча)

Существующий генератор постов (`postgen.py` + `case_model` + evidence-гейты)
построен вокруг **модели корпоративного кейса** (company/problem/
implementation/results/metrics) и классификации frozen-V2. У агро-практических
статей этих полей нет; натягивать их на case-модель = обманывать E/F-гейты и
ломать headline-механизм. Поэтому реализован **lane-модуль** — ровно тот же
паттерн, что уже принят платформой для «Новостей дня» (`news.py`), а не вторая
версия case-генератора:

- `case_pipeline/agro.py` — линия контента (discovery через общие адаптеры,
  fetch/extract общие, публикация общий `telegram.publish_post(channel="agro")`,
  дедуп — общий `storage.py`, но **отдельный файл БД** `data/agro_channel.db`).
- Пост **extractive**: заголовок и абзацы — дословно текст источника
  (LLM не участвует → числа выдумать нечем; гейт «числа ⊆ источника» всё равно
  включён как регрессионный контроль). AI-polish заголовков — следующий этап.
- News-полоса агро: материал с вердиктом `news` помечается `news_hold`
  (подушка). Текущий `news.py` для второго канала **напрямую не переиспользуется**:
  в нём хардкод AI-тематики (RELEVANCE_RX), обязательный GigaChat, один chat и
  content_type='news'. Рефакторинг под каналы — отдельный следующий шаг.

## Дедупликация и изоляция каналов

- `storage.py` **не изменён**: та же схема (materials, publications с `chat_id`,
  `content_type`). Изоляция — на уровне файла: агро пишет в `AGRO_DB_PATH`.
  Это минимальное доказуемое разделение (global `canonical_url UNIQUE` теперь
  глобален только внутри своего канала; взаимного блокирования каналов нет —
  проверено тестом). publications.chat_id дополнительно различает историю.
- В рамках канала: hard-dedup по canonical_url + case_id (`case_id_for` общий),
  мягкий повтор не переобрабатывается (тест), раса-сейф claim/release — общие.

## Что доисправлено этим проходом (по результатам проверок, не «на глаз»)

1. **telegram.send_message**: удалён исторический env-fallback
   (`token or config.BOT_TOKEN`, `chat_id or config.CHAT_ID`). Теперь low-level
   API требует явную пару; реальный prod-путь не изменился ( пара всегда
   передаётся из `credentials(channel)`), но второй канал физически не может
   молча уйти в чат первого. Тест: `test_send_message_no_prod_chat_fallback`.
2. **classifier_agro**: найдена живая ложная выдача — научная сводка Gismeteo
   «Эрозия болот… 380 тыс. тонн» проходила как practical (цифры+темы в теле).
   Правила ужесточены измерением на реальных материалах: practical требует
   A) пользу в заголовке+конкретику, B) 2+ обращения к читателю (-йте/-ьте), или
   C) цифровой список-заголовок с рубрикой в заголовке и БЕЗ новостных
   маркеров («сообщает/за период»). На 4 реальных статьях: 3 практических
   остались, эрозия → news. Регресс-тест закреплён. Gismeteo НЕ «проталкивается»
   — сейчас весь его контент честно `news` → `news_hold`.
3. **agro.run()**: смешанные фиды (журнал Агроинвестора отдаёт недельные статьи
   первыми) больше не сжигают бюджет прогона: stale/thin не считают
   «полезными», скан шире (до 4× лимита), окно свежести НЕ ослаблено.
